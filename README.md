# Hangman

Puzzle content (`src/data/*.json`, `src/data/puzzleManifest.json`, `src/data/puzzleCatalog.generated.ts`)
is generated by a private companion repo and copied in here as a complete drop-in unit — one
directory, `src/data/`. There's no build step in this repo anymore that regenerates them.

## Adding your own puzzle content without the private repo

You don't need access to the private scraper repo to add a new puzzle pack. `Puzzle` (see
`src/types/puzzle.ts`) is a plain, documented shape:

```ts
type Puzzle = {
  id: string                    // must be unique within its category -- stable per answer, since
                                 // win records (puzzle_unlocks_v1) are keyed by this id
  source: PuzzleSource
  type: 'phrase' | 'trivia' | 'title' | 'band' | 'song'
  answer: string                 // display text
  normalizedAnswer: string        // A-Z and spaces ONLY -- see below
  category: string
  difficulty: number
  difficultyTier: 'easy' | 'medium' | 'hard'
  wordCount: number
  letterCount: number
  uniqueLetterCount: number
  tags?: string[]
  metadata?: Record<string, unknown>
}
```

Important: the on-screen and physical keyboards only support A-Z. `normalizedAnswer` must contain
nothing but uppercase letters and spaces, or the puzzle is silently unwinnable.

To add a new pack by hand:

1. Write `src/data/yourPackName.json` as a plain array of `Puzzle` objects matching the shape above.
2. Add an entry for it to the `puzzleManifest` array in `src/data/puzzleCatalog.generated.ts`
   (`key`, `file`, `label`, `count`, `difficultyTiers`, `sources`, `categories` — all derivable
   directly from the array you just wrote) and a matching loader entry in that file's `loaders`
   object: `` 'yourPackName': () => require('./yourPackName.json') `` (same-directory require, since
   the data files and the generated catalog all live together in `src/data/`).
3. Run `npm run check` and `npm test` to confirm nothing's broken.

This is a small enough shape that a short script to automate steps 1–2 is easy to write yourself if
you're adding several packs — there just isn't a maintained one in this repo, since the canonical
version of that logic now lives in the private companion repo (which also runs it automatically
after every scrape).
