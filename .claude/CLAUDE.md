# Hangman

An ad-free Hangman word-guessing game (Expo/React Native). Part of the `@rific`/`@tastic`/InfiniteToken app ecosystem. It depends on `@rific/auto-paper`, `@rific/drawer`, `@rific/feedback-press`, `@rific/focus-chain`, `@rific/scroll-view`, `@rific/splash-gate`, `@rific/toaster`, `@rific/updater`, `@tastic/sprites` (the `./fireworks` subpath only, for the win-celebration burst; see `src/effects/FireworksCelebration.tsx`), `@tastic/hud` (the `./chrome` subpath only; see "Fleet chrome via `@tastic/hud/chrome`" below), and `@tastic/profile` (the fleet's player profiles, 0.16.2+: 0.16.1 added `OptionPickerOption`'s `color`, which the Single Player loadout's Difficulty rows use, and 0.16.2 tells a swatch renderer where it draws, so the chips stay flat; see "Players" below). `@tastic/sprites` was published as `@tastic/animations` until it was renamed; the old name is deprecated on npm, and Hangman switched on 2026-10-14 (the fireworks source is byte-identical). Still no Skia dependency: unlike the fleet's Skia-rendered games (BoxHockey, AirHockey, Snake), this app draws its gallows/word-reveal "modes" with `react-native-svg`, and `@tastic/sprites/fireworks` is itself SVG-based, so this app never depends on `@shopify/react-native-skia` at all. `@tastic/sprites` also has Skia-based subpaths (`./gravity`, `./shapes`, `./hockey`) that this app doesn't import; the package's subpaths keep each renderer's peer dependency scoped to only the apps that actually use it.

**Expo has changed.** Read the exact versioned docs at https://docs.expo.dev/versions/v58.0.0/ before writing any code - don't rely on general Expo knowledge, this app is on SDK 58 specifically (and expo-router 58: see "Routes and resume" below).


Always run `npm run lint` before finishing any task. This is an app (`"private": true`, no publish scripts) - `verify` doesn't include a build step.

**Builds and OTA updates:** the `build` and `update` scripts are plain `eas build` and `eas update`, with profiles in `eas.json` (`development`, `preview`, `production`). Pass the profile through, e.g. `npm run build -- --profile preview` or `npm run update -- --branch production --environment production --message "..."`. Nothing in them runs `verify`, so run `npm run verify` first. An OTA update also bumps `otaVersion` in `src/constants/release.ts` (the version label players see), committed before publishing. They used to be `@rific/updater`'s `rific-updater-build`/`rific-updater-update` bins, which @rific/updater 0.7.0 removed; the package stays for its OTA update hook. `build:web` is the one exception: it chains `npm run verify && expo export -p web` inline.

**A real regression, found and fixed as part of this migration: a manual mock under `src/__mocks__/` for a deep SUBPATH of a node_modules package is not reliably auto-applied the way a bare package-name mock is.** Every mock listed above for a *bare* package (`react-native-reanimated`, `expo-audio`, `redux-persist`, `@rific/scroll-view`, etc.) works with zero registration, matching this package's own documentation. But `2 of 30 suites` (`PackPuzzleList.test.tsx`, `PnpFlow.test.tsx`) started failing after the pure file-extraction pass, both on assertions sensitive to a react-native-paper `<Button icon='...'>`'s rendered text - instead of an empty icon slot, the raw MaterialCommunityIcons font glyph character showed up before the label. Confirmed directly, not guessed: a `console.warn` planted in the real (un-mocked) `@expo/vector-icons/build/MaterialCommunityIcons.js` and in react-native-paper's own compiled `MaterialCommunityIcon.js` fired during a failing test with a same-shaped mock file already sitting under `src/__mocks__/` for both, and did *not* fire once each was registered - and, separately, that `import * as RNPaper from 'react-native-paper'` (ESM, in real app/test code, transformed by `babel-preset-expo`) resolves to `react-native-paper/src/index.tsx`, while a plain `require.resolve('react-native-paper')` call resolves to `lib/commonjs/index.js` instead - two different real files, confirmed by the same technique. This app's own pre-migration `jest.setup.ts` never hit this, because it always registered every one of these subpaths with an explicit `jest.mock(path, factory)` call - the migration only moved the factory *bodies* out, and dropped the registration itself along with them. Fixed by keeping an explicit, no-factory `jest.mock('specifier')` call in `jest.setup.cjs` for every subpath mock (bare-package mocks still need none), so Jest is told to use the adjacent `src/__mocks__/` file rather than relying on auto-discovery. One further gap surfaced in the process and needed a fresh mock, not just a registration: `Theme.tsx` imports `@expo/vector-icons/MaterialCommunityIcons` (no `/build/`) directly to preload the icon font - a real module this app's own original `jest.setup.ts` never mocked either, but registering only the `/build/` subpath wasn't enough to stop *this* import from loading the real font-glyph component. That one is an inline factory in `jest.setup.cjs` rather than its own `src/__mocks__/` file, since a bare registration for it alone didn't reliably pick up an adjacent file either. **Flagged for Jay below** - this likely affects other already-migrated apps with subpath mocks (`redux-persist/integration/react`, `@expo/vector-icons/createIconSet`, etc.) that simply never had a test assertion sensitive enough to catch it.

**Migrating onto `@infinitetoken/tsconfig/expo` turned on `noUnusedLocals` for the first time**, surfacing 19 dead `import React from 'react'` statements (leftover from before the `react-jsx` transform made them unnecessary) across `App.tsx`, `src/__tests__/App.test.tsx`, `src/components/GameVisual.tsx`, `src/components/SketchWord.tsx`, and 15 of the `src/modes/*.tsx` visual-mode files - removed (three of them, `jenga.tsx`/`snowflakes.tsx`/`stars.tsx`, kept their `{ useState }` named import, only the default `React` import was dead). Also one dead reduce-callback parameter, `src/modes/letters.tsx:22`'s `(acc, w, i) =>` - `w` was never read (the running cursor uses `widths[i - 1]` instead) - renamed to `_w` rather than removed, since the used `i` parameter comes after it positionally.

`@infinitetoken/eslint-config` (`^0.2.0`), `@infinitetoken/jest-config` (`^0.2.3`), and `@infinitetoken/tsconfig` (`^0.4.1`) are all on real published versions - never yalc-linked for this app.

**`@rific/scroll-view` was briefly yalc-linked (`file:.yalc/@rific/scroll-view`) for a real bug - resolved 2026-09-11.** `ScrollViewProvider`'s `headerHeight` state could get stuck at `null` forever on web if a `<ScrollViewHeader>`'s `onLayout` simply never fired on the very first mount through Expo Router - every screen this app wraps in a `ScrollViewProvider` (`PackPuzzlesDrawer.tsx`, `PacksScreen.tsx`) stayed at `opacity: 0` until `headerHeight` resolved, so this was making this app's entire UI render invisible on first web load. ## Testing

- Framework: Jest (`@infinitetoken/jest-config/expo`, `jest-expo` preset)
- Tests live in `src/__tests__/`, mirroring the source subfolder structure (`components/`, `effects/`, `hooks/`, `utils/`)
- Native/Expo module mocks live in `src/__mocks__/`, one file per module (including several scoped subpaths) - a bare-package mock is picked up automatically, but every subpath mock needs its matching explicit `jest.mock('specifier')` call in `jest.setup.cjs` too (see Tooling above for why)
- `jest.setup.cjs` holds only genuine setup-file concerns: the explicit subpath-mock registrations, process-level error handlers, the `IS_REACT_ACT_ENVIRONMENT` flag, and this app's own Animated-JS-driver-forcing + `NativeAnimatedModule` synchronous-callback patches. The RAF polyfills and no-factory `NativeAnimatedHelper` automock it used to carry were removed on 2026-10-02 as no-ops: `@react-native/jest-preset`'s own setup (pulled in by `jest-expo`, and run before this file) already defines `requestAnimationFrame`/`cancelAnimationFrame`, so the `typeof ... === 'undefined'` guards never fired, and `react-native/Libraries/Animated/NativeAnimatedHelper` doesn't exist in RN 0.86 (it moved to `src/private/animated/`), so that `jest.mock()` call always threw into a bare `catch` and never applied
- RNTL 14's `render`/`rerender`/`unmount`/`fireEvent` are all async: always `await` them. `render` only queues its tree for the automatic afterEach unmount once its own promise resolves, so an un-awaited `render` (App.test.tsx did this until 2026-10-13) leaves the whole app mounted, timers still firing, after the file's Jest environment is torn down.
- Anything that reads the active player (stats, rounds, puzzle unlocks, art, difficulty, packs, colors) needs the app `store`; reset `activePlayer`, `playerSettings`, `playerTheme` and `profiles` (`profilesActions.setAll([])`) (and `round`, `achievements`) in `beforeEach`, and give a hand-built test store the `activePlayer` reducer. Drawer tests wrap in the store and `CatalogProvider`. A profile made active before `Providers` mounts has to be on the roster, or `ProfilesProvider`'s launch reconcile forgets it and the guest plays. At the Pass & Play table (its page and games) a guest seat plays as its own guest, `guestSeatKey(seatId)`, never `GUEST_PLAYER_KEY`: seed a table guest's picks, colors and rounds under the seat's key, and the active player reads `{ profileId: null, seatId }`. Under Jest there is no shared roster (no App Group module, not the web), so the roster is the store's own copy; `useProfiles.test.tsx` fakes the shared store at its native end (expo-modules-core's `TasticProfile` module) to run the package's real sync. @tastic/profile's pickers only show their popover once hud's `useAutoAlign` has measured the trigger, and the jest preset's View never answers `measureInWindow`, so a test that opens one spies `View.prototype.measureInWindow` to call back (see `LoadoutScreen.test.tsx`).
- Nothing in an always-mounted subtree (the drawers stay mounted while closed, and Home and the loadout stay mounted under the screens pushed over them) may run timers while hidden. ModePickerDrawer's card demo loop used to, so every test rendering the old Main or App fed React real-timer updates for as long as the tree lived. On a slow CI runner that turned one test hitting the 5s timeout into a whole file of timed-out tests and timed-out RNTL cleanup hooks, and CI run 37263959211 then hung until GitHub's 6-hour limit (fixed 2026-10-13: the loop pauses while the drawer is closed). Its carousel is back on the Single Player loadout (`ArtCarousel`, 2026-10-18), where it plays while the page is in view, so the loadout's screen tests stub the whole carousel (`LoadoutScreen.test.tsx`, which reads only whether the page paused it) and its own suite stubs the loop (`ArtCarousel.test.tsx`).

## OS portrait lock (2026-10-08)

Hangman is portrait-only and, unlike the @tastic games, draws no rotation of its own; nothing here lays out for a landscape window. It still takes `@tastic/core` for its Expo config plugin (`["@tastic/core", { "drawsRotation": false }]` in `app.json`'s `plugins`); its JS only arrives indirectly, through `@tastic/hud/chrome`, and nothing here mounts its `OrientationProvider` or draws rotation. The plugin owns the native lock: `orientation: "portrait"`; `ios.requireFullScreen` plus an iPad list of Portrait and UpsideDown (without it Expo forces all four iPad orientations and an iPad turned sideways got this portrait layout in a landscape window; the cost is Split View, Slide Over and Stage Manager); and `android:appCategory="game"` (Android 16 and later ignore the portrait lock on tablets and unfolded foldables, except for games). `drawsRotation: false` is what keeps UpsideDown on iPad: with no app-drawn rotation, iOS's own 180 flip is correct here, while the @tastic games list Portrait only because they draw the 180 themselves. Don't set any of those by hand. Check with `npx expo config --type introspect`; it only takes effect in a new native build (`ios/` and `android/` here are gitignored prebuild output, regenerated by `npx expo prebuild`).

## Icons and splash (2026-10-13)

Seven games (AirHockey, BoxHockey, Hangman, LightCycles, Pong, Snake, Solitaire) and Expo-Starter use the same four files, `assets/images/icon-light.png`, `icon-dark.png`, `splash-light.png` and `splash-dark.png`, and the same `app.json` config. The icons are opaque 1024px squares on `#FAFAFA` (light) and `#050505` (dark). Each splash is its icon's art on a transparent background. The `expo-splash-screen` plugin paints the same two colors behind it, at `imageWidth` 200. `expo.icon` is `icon-dark.png`, `web.favicon` is `splash-dark.png`, `ios.icon` is the dark/light pair, and there is no Android `adaptiveIcon` (Android uses `expo.icon`). The favicon is the transparent splash art, not the opaque icon, because it looks better in a browser tab (2026-10-16), so `splash-dark.png` has to read on both light and dark tabs. Snake is the only game whose light and dark art differ (its body and head fill). The other games keep two identical splash files so the config is the same everywhere. Icon and splash changes only take effect in a new native build.

## Fleet chrome via `@tastic/hud/chrome` (2026-10-15)

Hangman uses the fleet's shared UI from `@tastic/hud`, but only through its light `./chrome` subpath (added in hud 0.15.0 for this app). The main `@tastic/hud` entry also re-exports the per-seat lobby, `AchievementUnlockList` and the Skia gauge, so importing it would require Skia and `@tastic/split-screen`, which this app doesn't have (it has `@tastic/profile` since 2026-10-17: 0.16+ imports hud only through `./chrome` too). `eslint.config.cjs` blocks the bare `'@tastic/hud'` specifier with `no-restricted-imports`. `.npmrc`'s `legacy-peer-deps=true` means npm won't warn about a missing peer, so the lint rule and `npm ls @shopify/react-native-skia @tastic/split-screen` (empty) are the guard. `@tastic/achievements` runs the app's stats and achievements (see "Achievements and stats" below); `tsc` also needs it because it type-checks hud's raw source (the `react-native` export condition) and `AchievementCatalogSection` type-imports it.

The card only appears in non-dev native builds (`@rific/updater` skips `__DEV__` and web).
- **Corners and Settings (2026-10-15):** the game screen uses hud's `CornerActionButtons` (plain `onSurface` glyphs: Home top-left since 2026-10-17, as in Solitaire, because a launch can open straight into a game with no loadout beneath to go back to (a back arrow to the loadout for the router pass's first day, the Game Menu before it); the Settings cog top-right) in place of the old filled red menu badge, and `PuzzleInfoRow`'s pills are padded and offset to sit level with and between them (the math is in its `hintSlot` comment). Customize and `ModePickerDrawer` are gone (its art carousel is back, on the loadout, as `ArtCarousel`: see "Routes and resume" > Loadouts); the player's color is the player picker's color page (see "Players"). - **Result card (2026-10-15):** `RoundEndDialog` is hud's `OverlayBackdrop`/`OverlayCard` in a Paper `Portal`, like Solitaire's win and loss banners: a primary trophy and "You Won!" or a muted skull and "You Lost!", the answer written left to right in the board's sketch letters (`SketchWord`'s `letterColors`/`letterDelaysMs`; missed letters red on a loss: `colors.error` in light mode, MD3's error tone 50 `#DC362E` in dark, since the theme's dark error is a pale pink), any unlocks and pack progress, then Next. The card stops at the safe area and the answer, unlocks and progress scroll between the title and Next, so Next is always reachable; `fitAnswerFontSize` sizes the answer to the card's width and, down to 20, its height (the longest catalog answer fits a 375x667 phone without scrolling). `Game` hides the card and the fireworks itself on Next, because a shared-link puzzle's Next leaves for the loadout instead of remounting `Game`, and the web keeps a left screen mounted; it also hides them while `roundCardHidden` is set (Pass & Play's End Session card standing in, see "Pass & Play sessions"). A pack turn's card (the table on the packs, see "Pass & Play sessions" > Pack turns) is the solo card (its player's unlocks and pack progress) plus the same pieces: "Alice solved it." or "Alice missed it." (led by their chip), the standings with their row in bold, "<Name> is up next" (the next fair pick) and End Session; `PnpRoundSummary` is `{ playerId, playerName, playerProfile, writerName?, nextName, nextProfile, standings }`, a written word's with `writerName` ("writes next"), a pack turn's without ("is up next"). The height math covers both (the result and next lines, the standings, the stacked buttons and the progress row are all budgeted), pinned by a small-phone test of each. The height math (`CARD_CHROME_HEIGHT`) uses hud's current card: 24pt padding and no border. Unlocks come in blocks, one per player (`unlocks: RoundUnlocks[]`, `{ owner, achievements }`, an empty block not shown): a profile's headed by their name ("Alice Unlocked", beside their `ProfileChip`), the guest's keeping "Achievement(s) Unlocked" (a guest's progress is the device's), each announced as "<heading> unlocked: ...". A solo round has its player's block; a Pass & Play round the guesser's, then the writer's when the writer is a profile (a guest writer's is always empty: `recordPnpRound` gives the device's unlocks to the guesser). End Session swaps in `PnpSessionEndDialog` (Keep Playing or back brings the card back; Done is `endPnpSession` and leaves for the Pass & Play loadout, the last board staying drawn while it goes).
  - **Leaving**: the corners and Android back as on any game screen, back to the Pass & Play page (`door`), the turn kept for Ready; the page puts its focused seat back as the active player. A relaunch mid-turn comes back into it (`activeMode` `solo`, `activeDoor` `pnp`).
  - **Switching the source mid-session**: the standings carry on (seat-based, one `standings` for both), a turn under way stays for when the source is Packs again, and a written word left waiting (handed off, mid-guess or half typed) stays for when it's Write again (the pack turns never touch the written word's round). The edges: End Session from a pack turn ends the whole session, a written word left waiting included (as New session does, though its confirm doesn't say so); and Ready while the players write with nothing written and no standings starts a new session (`startPnpSession`), which clears a first pack turn still under way (harmless: with no standings the fair pick is the first seat again, and its round waits in the player's slot).
- **Turns:** whoever just guessed writes the next word (the writer changes when the next prompt opens, so a round resumed mid-guess keeps its own writer and guesser). The guesser is the fair pick: the other player with the fewest words guessed, ties going around the table after the writer; the writer can change it in the prompt's For row (three or more players only). The pick is saved, so it survives closing the prompt.
- **Whose board it is** (2026-10-18): the writer's while they write, the guesser's from the hand-off on (through the result card, whose Next has them write the next word anyway): `GameScreen`'s `PnpRound` makes whoever's turn it is the active player while the screen is the one showing, so the board is in their colors (`PlayerThemeSync`), the draft in the writer's art, and the handed-off word in the guesser's (`handlePnpAuthored` saves it with the guesser's art; `setRoundArt` only moves a waiting word for its guesser). The page puts its focused seat back when it's shown again.
- **Recording:** a written word's round counts into the standings and the stats the moment it's decided, once per round id (`recordPnpResult`), so a relaunch can't double-count it; stats go through `recordPnpRound` with each seat's `profileId` (null for a guest). A pack turn counts by `recordPackTurn` (see Pack turns).
- **Ending:** End Session (beside Next on the result card, a written word's or a pack turn's) swaps the card for `PnpSessionEndDialog`: the winner is the best win rate among players who guessed at least once, equal best rates tie, and nobody solving anything means no winner ("Nobody solved a word."). It's End Session's confirm: Keep Playing, or Android back, brings the round card back with nothing changed; only Done clears the standings (players kept) and leaves for the loadout. New session on the page also clears them, after its confirm.
- **Standings** (`PnpStandings`) are shared by the result card and the End Session card (the page shows them as badges); past four players they go to two columns so the card stays short.
- **Profile seats (2026-10-17):** every seat has a `profileId` (null for a guest). Its picker's popover is Guest, every profile, then Manage, `takenIds` every seated profile, so one profile sits in one seat. Reducers (`roundSlice`): `setPnpSeatProfile({ id, profile: { id, name } | null })` seats a profile (a profile seated elsewhere changes nothing) or hands the seat back to a guest named for its seat; `focusPnpSeat(id)`; `setPnpSource(source)`. Seating a profile in the focused seat makes them the active player at once; handing it back to a guest makes the seat's own guest active, with whatever they kept (see "Players" > A guest seat's lifetime). Two profiles may share a name, and a profile may share a guest's "Player N": their chips tell them apart.
- **Names:** guests are named for their seats, kept in step by the reducers as seats come and go (`numberGuests`; the sanitizer renames every stored guest the same way, so a guest renamed before 2026-10-18 comes back as their seat's Player N). A profile's seat keeps a copy of the profile's name in its `name` (normalized, at most 16), kept in step with the roster by the round slice's `extraReducers` on @tastic/profile's `setAll` and `update`, for the moment between a profile leaving the roster and being forgotten. The screens show the roster's own name, live (`getSeatIdentity`, `getStandingRows(session, profiles)`), with the profile for its chip. A forgotten profile's seats stay at the table as guests named for their seats, with their standings and the turn unchanged (`clearPnpProfile`, from `forgetPlayer`).
- **A seat's standing is the seat's** (2026-10-17 call): switching who sits in a seat keeps its standing, its turn as writer or guesser and a word waiting with it; whoever sits there carries them on. So switching a seat that has played this session asks first (hud's `ConfirmDialog`, like removing a player: "Switch to Bob?", "Bob takes over Player 2's standing this session: 1 of 1 solved.", Switch or Cancel; Android back cancels); a seat with nothing played switches straight away. Stats already recorded stay with whoever played those rounds; the seat's next round counts toward whoever sits there then (`recordPnpRound` reads each seat's profile as the round is decided).
- **Shown everywhere a seat is named** (see "Players"' who's who): the prompt's title and For row, the hand-off card, the result card's lines, standings and per-player unlocks (each profile's own, under their name; a guest's are the device's), the End Session card's winner, and the page's badges.

## Keep Awake (2026-10-17)

Jay chose to give Hangman Keep Awake (keep the screen from locking during a round: the OS auto-lock only counts touches, so a long think on a guess, or a Pass & Play hand-over, can lock a release build). `/game` (`src/app/game.tsx`'s `GameRoute`) calls `@rific/core`'s `useKeepAwake('game')`, released on unmount, unless the player turns off the Keep Awake row in Settings (default on, read live so the toggle applies mid-round). Expo only keeps the screen awake by itself in development builds.

- **The setting is core's:** `keepAwakeReducer` is mounted as `keepAwake` in `store.ts` and listed in the persist whitelist, and `Providers.tsx`'s `KeepAwakeBridge` (`initialValue` from the slice, `onChange` dispatching `keepAwakeActions.initialize`, the same bridge as the other games) mounts core's `KeepAwakeProvider` with `expoKeepAwake={ExpoKeepAwake}` (`import * as ExpoKeepAwake from 'expo-keep-awake'`), directly inside PersistGate so it is above every Portal.Host. Handing it the module is what turns the feature on: without it `useKeepAwake` does nothing and hud hides the row. A first per-game version (its own settings slice and `useSettings` hook, which also left `SettingsDialog.test.tsx` and `PnpFlow.test.tsx` red without a store) was reverted the same day in favor of this. Those tests render `SettingsDialog` with no provider and still pass: core's context falls back to an inert default (setting on, no module), so the row just stays hidden there.
- The row is `@tastic/hud`'s (0.23.0+): `BaseSettingsDialog` reads core's setting itself, with no props, and shows the row (caption "Stop auto-lock mid-match") only when `useExpoKeepAwake()` returns a module and the device is touch-first (native and touch-first browsers). Needs `@rific/core` 0.4.0+.
- `expo-keep-awake` is a direct dependency (`~58.0.3`, via `npx expo install`). It was already in native builds as a dependency of `expo`, so no new native build is needed.
